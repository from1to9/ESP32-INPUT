# Wi-Fi service tests

Run `python3 tests/wifi/run.py`. It compiles the actual [service](../../firmware/main/app_wifi.c) with deterministic substitutes at the ESP-IDF radio, netif, HTTP, clock, task and NVS boundaries. The service's production worker initialization/step functions and actual HTTP handlers are exercised directly; no test-only protocol or alternate service is used. AddressSanitizer and UndefinedBehaviorSanitizer cover the supported path. A separate no-Wi-Fi capability build checks explicit unavailable behavior.

Native-station checks cover queued asynchronous scan, driver retention configuration, fixed 32-row clipping/cleanup, one-row reads, same-name identities, unsupported auth, hidden/invalid/embedded-NUL/full-length labels, generation/TTL/cooldown boundaries, pending-join expiry, private local credential submission, Join once versus Remember and join, saved reconnect without AP, association versus DHCP/IP, and actual backend availability published by the independent TLS owner. Normal startup creates no AP netif; an explicit fallback allocation failure does not block native joining. Tests use synthetic credentials and do not print them.

Scan faults cover low free/largest-block heap, SDK admission/count/read failure, empty success versus failed scan, cancellation before/after SDK start, missing/late completion, timeout, scan-stop failure with bounded retries, list-clear failure/recovery, no reconnect or replacement while cleanup owns the driver, and forget draining active scan state. They exercise the production worker and documented SDK completion boundary; they do not claim driver internals or dense-radio behavior are simulated.

Editor reservation tests select a fresh row, expire/replace the display list, then submit the original five-minute ticket without reinterpreting its SSID. They reject ordinary stale-row joins, wrong ticket/SSID/index, unsupported selection, stale renewal, replacement/release/forget, replay, absolute ticket expiry and queued expiry. Consuming a ticket transfers it to the worker; an editor-close release cannot cancel that accepted request. Owned manager tests separate the native editor from each authenticated remote principal/session: foreign reserve, release, selected join and manual join cannot borrow or replace an unexpired ticket.

Fallback regression checks retain explicit setup/no automatic AP, one-time form submission, AP-only bind configuration, random-session replacement, exact Host/Origin, body bounds, fragmented reads/timeouts, duplicate/unknown/malformed fields, UTF-8/control rejection, HTML escaping, token replay, queued-save cancellation/expiry, saved-network reload, capped retry timing, RSSI/IP validity, local stop/forget, storage recovery and initialization cleanup.

Shutdown regressions inject AP-mode and HTTP-stop failures individually and together, both on local stop and expiry. They verify immediate admission/credential revocation, pending/error visibility, no hot loop under repeated local stop, one-second retry bounds, independent completion of the two resources and fresh setup after recovery.

The NVS substitute writes directly in set/erase and does not apply a staged transaction at commit, matching the pinned SDK. Fault cases include errors before mutation, errors after mutation, and a failed acknowledgement after a direct write/erase. Tests check unchanged runtime selection, sticky storage uncertainty across radio/setup success, explicit read verification without runtime switching, actual next-boot differences, and forgetting a corrupt/unknown record without a fabricated SSID. These are storage-boundary fault tests, not flash power-loss or wear qualification.

After preparing the normal pinned target build, run `python3 tests/wifi/compile_target.py` to compile only the service against that build's SDK/configuration and the HTTP server's header dependencies. It writes the object to a temporary directory and does not alter the shared build's CMake sources or flash a device. This source compilation is weaker evidence than linking the integrated firmware.

Device acceptance needs native scan/select/private password entry through its explicit five-minute selection ticket, DHCP, wrong-password/out-of-range reconnect, editing past display-list expiry, power-cycle persistence, forgetting, RSSI readings, dense-AP heap/load and BLE/USB HID under station scan/join load. The computer remains on its existing LAN. Separately test the explicitly selected fallback's browser submission, expiry/stop and unreachable listener after stop. The independent station TLS owner reports backend readiness; IP readiness alone cannot be recorded as Web/API readiness. Record board, host/browser, firmware/SDK and local evidence without credentials; do not infer these results from host substitutes or object compilation.

Multi-profile cases cover capacity eight without eviction, WIF1 preservation, two WFP1 banks, exact readback, save-only/named join/reorder/forget, revision and retained-result identity, authentication quarantine, bounded reconnect and unknown-store recovery. Maintenance blocks new writes/scans/setup while draining admitted cleanup. A radio failure after verified durable deletion reports the radio error while retaining known storage.
