# Production coordinator host regressions

Run `python3 tests/coordinator/run.py` from the repository root. The runner builds with strict C11 diagnostics, conversion/shadow warnings and address/undefined-behavior sanitizers, using a temporary output directory. It includes the actual [production coordinator](../../firmware/main/main.c) and links production `interaction`, `hid_engine`, `input_core` and `device_settings`; no coordinator decisions, gesture classification, idle policy or safety transitions are reimplemented in the harness. To diagnose one case, use `python3 tests/coordinator/run.py --case touch_release_has_one_freeze_interval`. The default always runs every case.

The tests invoke production `submit_intent`, `process_priority`, `physical_button`, `process_buttons`, `handle_intent`, `sync_interaction`, `process_motion`, `update_send`, `render_view` and the report sender. A fixed-storage FreeRTOS queue substitute preserves nonblocking admission, capacity, FIFO copying and reset semantics. A BLE boundary records report payloads and rejects obsolete/unready generations. Controlled time, raw button edges and synthetic IMU samples enter through the actual board/clock contracts. Rendered value snapshots are copied at the UI boundary while asserting display-lock ownership. Other boot-only operations fail immediately if unexpectedly invoked. No USB or Bluetooth stack, serial port, board or radio is accessed.

Display, settings and connectivity cases additionally invoke production `service_display`, `route_touch`, `allowed_in_overlay`, `service_pair_operation`, `input_link_snapshot`, `service_transport_switch`, `service_usb_selection` and `observe_input_link`. Configurable service doubles expose board power and brightness acknowledgements, settings save status, Wi-Fi snapshots and synthetic local setup credentials. They record accepted requests separately from eventual status: a brightness request never illuminates the mocked display automatically, an accepted disconnect immediately advances the mocked BLE generation and revokes readiness while leaving link-down asynchronous, and enabling USB never fabricates a mounted/ready/completed acknowledgement. Each HID trace records which transport received it. Real NVS coalescing, faults and durability are tested separately in the [settings-store harness](../settings_store/README.md).

The executable cases cover these required behaviors; their latest pass/failure evidence belongs in the [coverage record](../../docs/test-coverage.md):

- Emergency lock/release under queue saturation through both trusted internal and real touch paths, overflow cancellation, stale HID epochs and UI revisions, simultaneous safety priority, physical-only unlock and zero reports before later work. Bounded emergency slots preserve a valid Lock, reject a consumed wake gesture and wait for a queued BEGIN before deciding admission.
- Two-level nine-cell selection and editing, every bottom-row group, center reset and rejection of empty child cells; 64 characters sent in two 32-character batches; exact down/up traces without implicit Enter; cancellation before/after down/up and across the batch boundary; accepted-prefix retention after failure, mode/menu changes and a substituted link transition. Same/invalid mode requests and brief congestion must preserve an active send.
- Unscaled touch displacement with quarter/eighth fractional carry; gesture identity and lifetime; explicit drag preserved through movement, then released by menu, mode, explicit release or link cancellation; local takeover consumes its first gesture.
- Raw AI down/up classification at the 280 ms single/double decision and 899/900 ms hold boundary; no single-click after double/hold; contextual keyboard confirmation; hidden/changed modal context suppression; first-press remote takeover; queued double-click then hold; lost-edge recovery requiring a fresh full hold.
- Calibration/readiness and board-unavailable gates, immediate physical/touch suppression, one 150 ms touch-release freeze, haptic release freeze, transient congestion, duplicate/invalid/gapped IMU samples, local-only keyboard focus and silent Audio mode.
- Read-only UI snapshots for preview, unavailable audio/recognition, muted microphone, actual peer/target absence and display-lock refusal; explicit Ctrl/Command shortcut selection without sending the draft; Settings-only theme changes with stale-context/locked rejection.
- Shared quick-panel navigation through Status, Settings and Back preserves the primary mode, keyboard submode and draft. Keyboard/audio chooser entry rejects wrong-mode, invalid and nested requests without cancelling valid sends; chooser focus rejects hidden background actions, valid selections close and synchronize the acknowledged view, and stale selection/navigation cannot affect the new page. Same-value audio selection still closes and invalidates its old UI revision. Raw AI double-click toggles the quick panel, returns ordinary panels to it and leaves pairing/Wi-Fi confirmations owned by their explicit confirm/cancel controls. Every safe menu exit from Wi-Fi setup requests AP cleanup, clears displayed credentials and rejects stale restart intents. Navigation-only report traces contain neutral releases only and make no preference, pairing or forget writes.
- Display/Input page ownership for persisted preferences, range validation, unchanged requests, stale revisions, storage rejection and unavailable brightness. Settings pages through Wi-Fi reject hidden background actions in Mouse, Keyboard and Audio modes. Connectivity alone owns transport selection; Bluetooth and Wi-Fi detail pages own their respective operations.
- Exact 1/5/10/30-minute deadlines and Off; passive telemetry/render loops do not renew idle or write settings. Timeout changes start a full interval, clock regression rebases, callback activity survives a dropped intent, and absent brightness capability keeps input usable.
- Display sleep preserves active text send, drag and draft semantics. Entire touch/AI wake gestures are consumed, including delayed priority Lock/Release, a wake double-click/hold and remote takeover. Failed or pending brightness acknowledgement blocks control activation; polling does not retry continuously, and a fresh physical gesture can retry.
- Queue reset/overflow after a touch END callback must reconcile the idle model, release wake capture and retain the consumed token watermark. Fresh touch Lock/Release controls remain effective while only the AI double-click guard is active; a consumed wake gesture remains ineffective.
- Wi-Fi start acceptance versus active status, secret visibility only on the local setup page, close/Back/physical-double-click/Release/Lock exits, cancellation and stale confirmation rejection. Synthetic SSID replacement and pending operations prevent forgetting a different network.
- Explicit pairing confirmations, stale link-generation rejection, keyboard and mouse releases before disconnect, one accepted disconnect request, bounded failure, lock cancellation and separate open/close/forget/disconnect behavior. Disconnect preserves saved pairings. Settings and Wi-Fi records receive no pairing writes.
- Truthful battery/Wi-Fi RSSI/network/pairing/save-state snapshots, unknown evidence, unavailable audio, and a thousand repeated render/status updates without settings writes or context mutation. BLE RSSI is intentionally omitted from the product view. Bond-list rendering distinguishes unknown from empty, uses SDK identities without invented names, marks only verified current peers and bounds pagination across 32 cached records.
- Bluetooth/USB switching in both directions waits for keyboard and mouse releases plus the old adapter's final completion. Held-key/drag traces, text suffix retention, fresh target release barriers and all primary modes remain explicit. Connected suspended/failed/congested hosts block until the exact five-second timeout; disconnected hosts permit explicit offline selection without claiming release delivery.
- One-shot send-boundary hooks mark the final zero report in flight or fail the target during admission. Switch/pair services must read fresh completion evidence after that HID step. Connected origin-generation replacement aborts switching until a new explicit request; an actual disconnect permits the requested switch without a release-delivery claim. Across Add/Forget/Disconnect, replacement before disconnect acceptance aborts; the adapter's own acceptance-induced generation increment does not. Replacement after acceptance never triggers another disconnect: the pending operation waits for link-down or its deadline.
- Unavailable or subsequently failed targets cannot change/persist selection. Lock/Release cancels a pending switch and late completions cannot revive it. Old-generation sends are refused; a refused release retains the old transport. USB detach/reconnect never falls back to Bluetooth or replays discarded text, and inactive BLE changes do not alter the selected USB snapshot or sender.
- Selected USB is rearmed only after a reset-cleared, initialized, non-failed adapter snapshot; inactive/failed/uninitialized USB never auto-enables. Repeated polling enables once. The actual link observer discards stale queued work and retains the unsent draft suffix, blocks while unready, and requires keyboard/mouse zero reports before fresh input.
- Transport preferences reach storage only after switching completes. A rejected save remains an error even though runtime selection changed. Corrupt/unknown Wi-Fi storage can be explicitly forgotten without a configured runtime network; confirmation binds runtime/stored SSIDs and known/present/uncertain state, and failed cleanup/storage status remains visible.
- Memory diagnostics retain the first complete allocation failure across a thousand later failures, perform no logging or heap observation in the callback, and omit empty/partially published records. Six boot samples retain distinct internal-byte and internal-DMA free/largest values, reject a thousand excess stages without further heap queries, and repeat the same bounded history for late readers. Logging and heap observations use opt-in boundary fixtures; callback registration and all other boot-only operations still abort if called. The simulated publication boundary does not prove target concurrency, IRAM placement or heap headroom.

Assertions inspect output traces as well as lock/epoch/draft state. A safe final snapshot cannot hide an earlier stale report. Expectations use fixed protocol values and product thresholds, not private priority bits, display wording or haptic call counts.

These are deterministic, single-threaded host tests of coordinator helper paths. They do not run startup or the infinite `app_main` polling loop or validate FreeRTOS scheduling/races, LVGL pointer-event routing/pixel layout, physical debounce and timestamp accuracy, real sensor axis direction/calibration, BLE/USB delivery, TinyUSB endpoint ownership, SDK ABI compatibility or device behavior. Transport reset/replacement tests invoke the actual `observe_input_link` helper, including its cancellation, queue discard, link update and congestion handling. Earlier simulated BLE disconnect cases invoke the lower-level production APIs. Neither style proves FreeRTOS polling-loop scheduling. Preference reload is tested in the store; actual boot selection remains a separate integration check. The production target build and separate adapter/engine/interaction suites retain ownership of those boundaries.

For the aggregate host runner, execute this script with the same interpreter as `tools/check.py`, after the portable engine suite. The aggregate runner is owned by the integration conversation and is not changed here.
