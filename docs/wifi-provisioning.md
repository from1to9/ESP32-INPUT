# Device-side station provisioning

Open **Settings → Wi-Fi** and scan for an existing network. Select the network
and enter its password on the device. Wait for station status to show an IP
address. The controller stays on the existing LAN. The optional recovery
hotspot requires explicit activation. LAN control requires separate enrollment.

## Integration contract

The [app_wifi API](../firmware/main/app_wifi.h) is separate from device UI, the coordinator, board adapters and BLE. Startup calls `app_wifi_init()` once after shared NVS initialization. It owns Wi-Fi, the default STA netif and one low-priority worker; the fallback AP netif is created only on an explicit setup request. It never erases shared NVS or initializes Bluetooth. An `ESP_OK` action return means accepted, not connected, saved, scanned or stopped.

| Local API | Integration rule |
| --- | --- |
| `app_wifi_scan_start/cancel()` | Explicit asynchronous radio job; poll `app_wifi_get_scan_snapshot()`. Cancel immediately invalidates result access; actual driver/event/list cleanup is separately reported |
| `app_wifi_get_scan_record(generation,index,...)` | Copy one immutable row at a time; coordinator copies only the visible page. Generation/index identify a result, never a mutable visible row. Expired/stale access clears output and fails |
| `app_wifi_select_scan_record(generation,index,...)` | At a fresh explicit selection, issue one five-minute local-editor ticket pinning original SSID/auth and scan identity. Returned metadata includes ID, original identity and lifetime; no password |
| `app_wifi_release_selection(id)` | Close/cancel the unused editor ticket. Stale releases cannot revoke a newer ticket; a ticket already consumed by join cannot cancel the accepted worker request |
| `app_wifi_join(request)` | Private local submission of original SSID, password, remember choice and optional scan generation/index. The service copies bounded data; the caller immediately clears its copy. Passwords never enter the HID draft, logs, ordinary UI intents, API state or events |
| `app_wifi_get_snapshot()` | Runtime station, actual association/IP/RSSI, durable metadata and independent errors; an IP does not establish a backend |
| `app_wifi_forget_network/verify_storage()` | Explicit confirmed forget or bounded read reconciliation, including unreadable/unknown records |
| `app_wifi_start_setup/stop_setup()` | Explicit legacy fallback only, with the expiry/admission/cleanup contract below |

At a fresh explicit selection call `app_wifi_select_scan_record` and bind its ticket to the coordinator-owned private editor. Submit the ticket's original SSID, `selection_id`, original `scan_generation` and `record_index`; never parse the label back into a name. This one-slot reservation pins SSID/auth identity for five minutes independently of the display list's 30-second lifetime or a later scan replacement. It cannot be renewed from a stale row. A new explicit reservation replaces the previous unused one; closing the editor releases it. Exact ticket/SSID/identity mismatches, expiry and replay reject. Join consumes the ticket into its immutable worker request and rechecks its absolute expiry before work; closing the accepted editor does not cancel the join. Forget or fallback setup invalidates unused tickets; reboot retains none.

Ordinary row joins with `selection_id=0` still validate generation/index/SSID and the 30-second list lifetime at admission and execution. A selection ticket is an explicit local editing policy, not a silent bypass or conversion to manual. Manual/hidden WPA2 entry is separately explicit (all three identity fields zero) and needs a corresponding editor before UI exposure. Secrets remain write-only. The same worker now supports save-only, named join/forget and complete priority reorder through `app_wifi_profiles.h`; the join/scan cancellation contract stays separate.

`APP_WIFI_OBTAINING_IP` means association without valid IPv4. `lan_ready` requires actual association with the selected SSID and nonzero station IPv4; it proves neither Internet access nor server readiness. `backend_available/backend_error` are now copied from the actual station TLS owner by the control runtime. Before usable trust/listener readiness they remain unavailable, even with an IP. A running listener is separate from browser trust or successful client authentication. The [native UI extension](interaction.md#status-connectivity-and-display) owns private entry and rendering; the coordinator owns intent/epoch/editor handoff.

The public snapshot contains no credential/token. It distinguishes initialized/configured state, current SSID, IP/RSSI, disconnect/retry/pending state and operation/connection/cleanup/storage errors. `configured` and `ssid` describe runtime selection. `stored_data_known` establishes whether presence is known; `stored_data_present` is meaningful only then. `stored_ssid` is empty for absent, unreadable or uncertain storage. A corrupt record may be known-present without a usable SSID. `storage_uncertain/storage_error` survive radio/setup success; only an explicit successful save/forget/read verification resolves them. Verification never switches the runtime network. Permit forget/recovery even with no configured network or known SSID; never fabricate a name.

## Native scan, join and reconnect bounds

- One pending credential slot and coalesced control flags; only the worker calls Wi-Fi/NVS. A local request returns before radio/storage work. Forget invalidates queued joins and drains an active scan before clearing configuration. Stop/forget cannot interrupt an NVS write already in progress or undo applied bytes.
- One scan, 15-second deadline, 10-second refresh cooldown, 30-second result lifetime and one five-minute single-use editor selection. Driver `max_scan_ap_num=32` and a compact fixed 32-row application cache bound retained records. `count` is returned records; `capacity_reached` means the true nearby count is unknown. Same-name/different-BSSID/security rows remain distinct. Current/saved markers reflect observations at scan completion; age is explicit.
- Scan uses nonblocking SDK admission, 30..60 ms active dwell, 120 ms passive dwell and 30 ms home-channel dwell with coexistence background scanning enabled. It does not change global scan or regulatory settings. Provisional admission requires 32 KiB free internal 8-bit heap and a 16 KiB largest block. These are fixed foundation limits pending shared settings/profile implementation, not fake writable controls or measured radio/resource qualification.
- Scan, association/DHCP, fallback setup and pending station changes are serialized. Healthy-link scans are allowed; reconnect waits while the scan owns the driver. Cancel/timeout attempts scan stop at most once per second on error and drains its documented completion event before another scan/join/reconnect. A missing completion after two seconds reports error plus cleanup pending and retains ownership until evidence arrives; it never claims cancellation success. List-release errors retry once per second without hot looping. SDK records are retrieved one at a time, with final list clear on success/error/cancel.
- Rows expose original SDK name bytes, safe label, BSSID, channel, RSSI, exact auth category, generation/index and join reason. Labels escape unsupported bytes; hidden/malformed/non-UTF-8 rows cannot accidentally join an escaped/truncated name. The SDK's NUL-terminated SSID representation is not a lossless arbitrary embedded-NUL SSID contract. Native joining validates nonempty printable UTF-8 names through 32 bytes and printable ASCII passphrases of 8..63 bytes. Scanned WPA2-Personal and WPA/WPA2 rows are joinable with an explicit WPA2 minimum; other categories remain visible/unavailable. No new WPA3/OWE/enterprise/open/WEP/WPA1-only or raw 64-hex-PSK capability is claimed.
- Join once changes RAM only and leaves durable metadata/uncertainty untouched. Remember and join upserts/promotes a profile in checked `WFP1` catalog banks before runtime switching; no silent eviction at eight profiles. Valid legacy `WIF1` bytes are loaded when banks are absent and retained during migration. A failed write keeps the previous runtime selection but cannot promise old flash contents. The next boot can read a replacement already written before an error. Named forget and explicit forget-all update the bounded catalog and remove the matching/explicitly reset legacy key, never a whole-NVS erase or bond reset. The old unnamed forget API rejects multiple profiles; unknown-catalog recovery requires the explicit acknowledged forget-all path. Driver credential storage is RAM-only.
- Worker poll is 200 ms; association/DHCP attempt is at most 15 seconds. Retry delays are 1/2/4/8/16/30 seconds and remain capped without allocating jobs. Success resets backoff. Saved-profile attempts follow enabled priority order; authentication failures quarantine that profile for five minutes. A join-once network never silently becomes a stored reconnect choice. Failure never opens an AP. RSSI validity and IP are cleared on loss/switch; association and assigned IP remain separate.
- NVS set/erase/commit errors do not guarantee rollback: flash may contain the previous record, replacement or no record. Keep sticky uncertainty and explicit recovery; no other radio/UI success clears it. Development flash/NVS is not encrypted by this service. Application credential copies are cleared after use; SDK/socket/browser copies and physical flash erasure are outside that guarantee. No real credential is logged or retained in Git.

## Optional fallback hotspot

Only an explicit fallback request opens a ten-minute WPA2 SoftAP, with a fresh 24-hex-character password and independent 128-bit form token. Only that fallback asks a phone/computer to join the temporary AP and open its displayed URL. The normal native station workflow does not. No AP starts at boot, reconnect failure or scan failure; AP netif allocation failure does not prevent native station joining.

The fallback has one client, two HTTP sockets/routes, a 512-byte form bound, exact AP-IP Host/Origin validation, token/generation/deadline checks, UTF-8 validation and escaped HTML. Its HTTP listener binds the AP netif using `if_name`, serves GET `/` and POST `/configure`, and provides no input/settings/update/shell API. HTTP has no application TLS inside the WPA2 setup network. Anyone given that temporary AP password can submit; do not confuse it with LAN authentication or a captive portal. No captive DNS, arbitrary CORS or automatic portal detection is promised. HTTP 202 acknowledges admission only; the form never echoes the submitted station password.

`app_wifi_get_setup_info()` is a trusted local-display API, separate from ordinary snapshots. Clear its password copy after close/expiry; never log or export it. Setup expires after ten minutes or closes five seconds after the submitted network actually connects. Stop/expiry/failure immediately revoke admission and clear setup secrets. Worker shutdown tracks HTTP stop and AP-to-STA mode independently; outstanding failures retain `cleanup_pending`, `setup_active`, `operation_pending` and cleanup errors, and retry no faster than once per second. Repeated stop cannot hot-loop. Do not show a usable password or offer another setup while cleanup remains pending. No token survives stop and setup never automatically reopens.

HTTP tasks have two-second socket waits plus a four-second fragmented-body budget. Radio/HTTP shutdown is not performed in HID/UI callbacks; actual interruption and radio shutdown bounds still require device tests.

## Saved catalog, maintenance and evidence

The catalog stores eight WPA2-minimum profiles in two fixed 1,068-byte CRC/generation banks. Every write verifies exact readback; an error may already have applied. Corrupt/ambiguous banks fail closed until explicit reconciliation or acknowledged forget-all recovery. Reorder validates a unique complete permutation and keeps a healthy station connected. Result snapshots expose exact request/completion IDs; eight terminal manager results are retained, and evicted/absent results are unknown. `app_wifi_profiles_forget_all_request` plus `app_wifi_profile_result` lets reset orchestration prove its own durable result.

`app_wifi_set_maintenance` closes new scan/join/profile/setup admission, invalidates private setup submissions and drains already admitted cleanup without dropping the active station link needed for update. The coordinator waits for actual worker/persistence/media/HID acknowledgement before flash work.
