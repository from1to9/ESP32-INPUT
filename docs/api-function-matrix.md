# Complete device API and configuration inventory

Status: source/API coverage contract, 2026-10-21. The generated [catalog](../api/control-v1.json), [OpenAPI](../api/openapi.json), firmware registry and [MCP metadata](../bridge/tools.json) now implement typed interfaces. Rows below define semantics; actual per-operation/provider availability and validation evidence govern use. Source presence is separate from physical/host qualification.

The [shared configuration contract](configuration.md) owns schema, staging/apply, durability and migration rules. [Remote control](remote-control.md) owns sessions/leases/input evidence; [Wi-Fi and OTA](wifi-management-ota.md) owns network/update job mechanics. This matrix owns command coverage and proposed stable field names. Board/build profiles and immutable safety rules remain separate from normal writable preferences. The [audio/recording plan](api-audio-recording.md) owns codec/storage/media evidence and negotiated limits. Its canonical operations, field names, seconds/bytes, scopes, grant transfer and unsupported-v1 states are aligned below; no second validator or transport-specific mutation path is permitted.

## 1. One registry, transport-independent behavior

Except session/upgrade transport bootstrap, all product mutations use **`POST /api/v1/commands` with a registry `op` and typed arguments**, or the same envelope over authenticated WSS. There is one validation/admission/dispatch path. Device UI intents and MCP tools derive from this registry and the same configuration metadata; do not build parallel setters or a permissive set-any-key tool. Proposed MCP names replace dots with underscores and use the same argument/result schemas. Protocol adapters never call BLE, USB, codec, GPIO or NVS directly.

Read-only resources are `GET /api/v1/state`, `/capabilities`, `/operations`, `/config/schema`, `/config`, `/jobs/{id}`, `/wifi/scans/{id}`, `/wifi/profiles`, `/bluetooth/peers`, `/firmware/releases` and `/recordings`. Exact authenticated media/file reads are separately bounded resources, not command-frame payloads. Cached reads never trigger a scan, recording or download. Authenticated `/api/v1/events` subscriptions expose versioned state/job/availability events with scopes and redaction; event gaps require a replacement snapshot, never input replay.

Wi-Fi is a background network service. Bluetooth/USB are selected HID output transports. A management request identifies the device and its management generation, not a HID host. It never silently changes mode/transport or sends input. Input commands additionally identify the selected transport, target, input epoch and lease. Wi-Fi loss cancels a remote input lease; it does not redirect local input or disconnect a HID host just to represent network loss.

Guard abbreviations used in every row:

- **I:** `input.control`, exclusive input lease, unlocked, correct input epoch/target/transport generation/mode, deadline and release barrier; recheck before every report.
- **U:** I plus captured UI/selection revision for context-sensitive device UI actions. Remote virtual gestures cannot fabricate physical presence, local takeover or wake/idle activity. Physical routing consumes the whole first asleep gesture before takeover/normal handling; a fresh local gesture after that guard takes over.
- **M(scope):** authenticated named scope, unlocked mutation, device/boot/management generation, resource revision and one bounded manager job. No HID lease is implied. Input-affecting apply additionally needs the coordinator barrier and must not steal active local ownership.
- **S(scope):** authorized safety stop/mute/cancel/lock, no owner lease required; current authenticated context, neutral-only effect. This never unlocks or expands scope.
- **C(scope):** `config.stage`, `config.apply`, `config.cancel` under the scope and metadata for the affected fields. Stage is inert. Apply rechecks guards, dependencies and required release/reconnect/restart policy. No duplicate per-field HTTP setter.
- **P:** explicit purpose-bound consent/standing owner-enrolled grant plus visible capture indication, finite job bounds and qualified resources. An in-grant authenticated start needs no repeated local confirmation; another principal or expanded ceiling needs the owner enrollment flow. A normal input/admin scope is not microphone consent. Mic capture prevents screen blanking on this board; only qualified readable dimming is allowed. Missing/stalled indication rejects/stops capture.
- **A:** a current administrator-authorized background policy can supply scoped approval within its exact principal/source/channel/version/size/time/maintenance/restart limits. It is not a blanket superuser bypass. An authorized remote admin may enable/revoke such a policy through C(`admin.policy`) without requiring a physical confirmation for every subsequent matching update. Initial principal trust/scope enrollment and physical unlock remain protected.

Lifecycle abbreviations: **D** = admitted -> manager applied/rejected; **H** = admitted -> report progress -> sent/cancelled/failed; **J** = admitted -> bounded job -> explicit terminal/cleanup state; **K** = configuration stage/apply/effective/save evidence. `accepted` is admission only; `sent` is transport API acceptance, not host UI success. `observed` is separately attributed external evidence. Current preview removal follows key-down acceptance; API progress must expose `started_prefix`, completed down/up pairs and any uncertain character separately, without requeueing a possibly typed character.

Common errors apply to every row: malformed/oversized/unsupported arguments, unauthenticated/forbidden, not implemented/unqualified/unavailable capability, locked, stale generation/revision/target, ownership conflict, deadline expired, queue/resource busy, cancelled, apply failure, storage uncertainty and unknown result. Each row adds its specific error/cancel boundary. No unsupported function returns a success-shaped stub.

Status **L** means a local source path exists, not universal hardware qualification; **U** means its current local output is unavailable/placeholder; **P** means new functionality is planned; **X** means intentional physical/build-only restriction. **LAN/MCP schema and adapters exist; runtime capability/provider state decides availability.** Runtime capability evidence is required before enabling either local or remote operation.

Remote activation of the device IMU is implemented through the shared coordinator: authority/owner and selected producer are represented separately, while one authorized producer feeds the production gate. An authorized remote owner may explicitly select the leased device-IMU producer without a local handoff. Scripted movement and IMU production are mutually exclusive; reject producer-conflicting commands rather than combine streams. It must not call BLE directly or claim a toggle works while the existing local-only gyro gate rejects it. After the whole asleep wake-only gesture is consumed, a fresh local touch/AI gesture takes over immediately; lease expiry stops the leased producer. Remote virtual gestures cannot create physical wake activity or change that ordering. Physical raw AI/BOOT/POWER GPIO injection and remote unlock remain X, with their semantic safe alternatives explicitly listed.

### Private local editor and authenticated remote commands

Wi-Fi/password and device-name drafts use the coordinator's bounded private `app_local_edit_request_t` submission, carrying editor session/purpose, epoch/UI revision, actual trusted gesture context and a fixed tagged payload. This local callback is not a new LAN endpoint or a physical-event injection API. Validate whole-wake consumption, takeover, lock, editor deadline/session, captured network identity and pending-slot ownership before consuming it. Password characters never enter the HID draft or ordinary intent/status/event/log payloads.

The UI clears its complete temporary submission request after every callback return. It clears the local draft immediately on `ACCEPTED` or `STALE`, and on cancellation, close/back, session replacement, expiry, lock, screen-off or shutdown. Rejected admission (`BUSY`, `INVALID` or `UNAVAILABLE`) may retain the draft only inside the still-valid local editor for deliberate retry. The coordinator clears an accepted private-slot copy when consumed or cancelled, and clears its temporary manager-request copy after handoff. The service separately owns and clears its bounded temporary credential copy during worker processing, including rejected/failed work; authorized driver RAM and durable credentials follow their own storage lifetime.

For native Wi-Fi, reserve at credential-editor open from a fresh row; submit the exact original SSID/generation/index and `selection_id`. The five-minute reservation survives the list's 30-second expiry/replacement; ordinary unticketed row joins remain strict. It is consumed once, cannot renew from an expired row and cannot be repurposed for another SSID/auth. Close releases only an unused ticket; it cannot cancel an already admitted join. The resulting owner is the existing Wi-Fi worker and its storage/reconnect path. Local Bluetooth-name submission enters the existing BLE name worker and validated settings owner; save follows actual applied-name evidence rather than optimistic text change.

Authenticated remote clients use canonical `wifi.join` or `config.stage/apply/cancel` with `bluetooth.device_name`, their own M/C scopes, resource revisions, write-only secrets and manager admission. They cannot submit into a local editor, borrow its selection ticket, read its draft, assert a trusted gesture or satisfy physical trust/unlock. Permitted remote settings need no blanket physical prompt; this boundary preserves local input ownership and secret isolation. Remote selection tickets bind their authenticated principal/session and management generation in a separate owner domain. Native and remote requests share the manager without borrowing one another's tickets. These LAN/MCP paths are implemented; backend readiness still depends on actual enrollment, station and listener state.

Recording is a planned first-class family, not a forbidden control-channel feature. Media bytes use a separately authenticated bounded channel/file resource with explicit storage/export consent; they do not fit inside 2 KiB command frames. No codec/recording/stream is functional until the owning audio plan, driver/resource integration, schemas and tests exist. Stored recordings are not ordinary configuration records; retention/deletion/power-loss semantics must be explicit.

### Audio/recording binding and initial-v1 limits

The [audio/recording plan](api-audio-recording.md) owns concrete defaults, media framing, quota/storage, consent, cancellation and artifact semantics. Canonical scopes are audio.control/capture/playback, recording.control/configure/read/export/delete, capture.consent and admin.privacy. No audio.configure/audio.stream/recordings.* scope aliases. Audio and recording use management/audio generation and expected resource revision, never a HID-target lease or input.control as an extra permission.

All desired values use config.stage/apply/cancel with exact keys below. No independent volume/config patch or audio-authorization setter. Runtime audio.enable.set, role-specific enable/mute and operational start/stop commands normalize to the same manager transitions with their registered scopes; saving a preference does not capture/unmute.

Default media is session-bound and stops on bounded owner-channel/session loss. File-only continue_local needs its source consent **and a distinct background_grant_id**, an enrolled capture.consent delegation with purpose background_recording. Successful transfer is explicit; it may continue without any HID lease and after its owner channel is gone, within both grants. All live egress stops; lock/privacy Stop/revoke/maintenance/indicator loss still terminate it. A saved grant is permission, never resumed active state.

On this board readable on-screen capture indication prevents blanking; qualified dimming is allowed, no initial screen-off/LED substitute. Failed indication rejects/stops capture; failed hardware stop retains the warning. Pause/resume/seek, partial-content reads and destination export are **unsupported initial v1**. No stop/start alias, paused writer, fake seek, silently downloadable partial file or read-as-export result.

Initial file recording requires owned encrypted NAND, protected keys, actual geometry/free-space and a qualified retention/clock/recovery policy. Unknown time/expiry after reboot is a truthful unavailable/quarantined state, not a false retention or export promise. No raw paths, implicit call recording, automatic quota-driven oldest deletion or silent sample loss. Metadata can report partial/error objects; finalized content requires integrity/ACL/export-policy checks.

Media budgets come from the owning resource profile: candidate 192 KiB audio pools plus separately measured TLS/filesystem budgets; one 8 KiB file buffer, Range<=256 KiB, default 128 KiB/s and 5 s inactivity; exact 40-byte stream header and<=1920-byte payload. These are qualification ceilings/metadata, not extra conflicting normal setters. No interface is implemented by publishing them.

## 4. Configuration field inventory

Every entry is metadata for the common C family: key, type/default/unit/range, capability and scope, apply policy, runtime/desired/saved evidence, explicit persistence, dependencies and tests. **B** = currently implemented baseline value; **P** = proposed configurability; **R** = read-only board/build/safety ceiling. An unavailable/default-from-profile value is not a writable unbounded setting; its driver must publish concrete choices before exposure. Existing algorithm validation is a source ceiling, not proof every value is hardware-qualified.

Apply codes: **now** (manager acknowledgement), **release** (input/gesture barrier), **link** (reconnect/resource transition), **maintenance**, **restart**. Persistence **D** = explicit durable/coalesced preference, **V** = volatile/session, **I** = installation/board profile. Do not write unchanged values, boot defaults, sensor frames, reconnect attempts or lease heartbeats. Multi-manager apply cannot promise atomic hardware rollback; flash errors retain uncertain storage even if an independently known old record exists.
